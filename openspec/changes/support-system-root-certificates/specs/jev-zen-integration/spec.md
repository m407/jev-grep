# Spec Delta

## ADDED Requirements

### Requirement: Автоматическое доверие системным корням

На поддерживаемых Linux, macOS и Windows клиент SHALL по умолчанию использовать доверенные корневые сертификаты ОС при HTTPS-оценках. При отсутствии переопределений источника сертификатов в окружении установленный доверенный CA SHALL применяться без экспорта в отдельный файл и без настройки `jev-grep`. Доверие SHALL одинаково действовать для одиночной и групповой оценки с сохранением проверки цепочки, имени узла и срока действия.

#### Scenario: Корень установлен непосредственно в ОС
- **WHEN** доверенный тестовый CA установлен в штатное хранилище ОС до запуска клиента, переопределения источника сертификатов отсутствуют и HTTPS endpoint предъявляет действительный сертификат для своего имени, подписанный этим CA
- **THEN** одиночная и групповая оценки принимают корректные ответы API без ошибки TLS и без специального параметра сертификата

#### Scenario: Частный корень не установлен
- **WHEN** сертификат endpoint подписан частным CA, отсутствующим во всех используемых источниках доверия
- **THEN** клиент завершается кодом 2, не отправляет HTTP-запрос через неподтверждённое соединение и не повторяет отказ проверки TLS

#### Scenario: Доверенный издатель не отменяет проверку сертификата
- **WHEN** CA доверен, но сертификат endpoint просрочен либо не соответствует имени узла
- **THEN** клиент завершается кодом 2 без HTTP-запроса и повторов отказа проверки TLS

### Requirement: Совместимость встроенного доверия

Системные корни SHALL дополнять существующий встроенный набор доверенных корней. Отсутствие сертификатов в системном источнике SHALL NOT отключать встроенное доверие или проверку TLS.

#### Scenario: Пустой системный источник
- **WHEN** системный источник не предоставляет сертификатов, а endpoint предъявляет действительную цепочку до встроенного доверенного корня
- **THEN** TLS-проверка проходит и клиент обрабатывает ответ API по обычному контракту
