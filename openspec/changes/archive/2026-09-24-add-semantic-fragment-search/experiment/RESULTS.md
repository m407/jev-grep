## Dataset and labels

`dataset.jsonl` is synthetic (no private logs): the original seven cases cover Gradle stack trace, retry/recovery, useful neighboring event, independent npm and Buildah failures, npm and Buildah output, and a client byte-limit marker. An eighth generated case (`context-edge-english-512`) creates a 10,215-byte single-record diagnostic using the fixed prefix/repeated suffix/count in the corpus row. The 124-byte row remains explicitly just a client byte-edge check. The added case is the context-limit experiment under the approved published-config assumption.

## Reproduction after endpoint authorization

Build the binary with `cargo build --locked --release`, then configure `LG_API_URL`, `LG_MODEL=english`, and `LG_API_KEY` locally if required. Run `experiment/run.sh`. It preflights `/health`, makes a synthetic identity probe and a separate real-inference telemetry probe for the long case, records effective CLI parameters and returned metadata/usage in `run-metadata.json` and per-case files, and refuses to proceed if health/usage verification fails; it never installs or starts a server. `LG_EDGE_LIMIT=128`, `LG_CONTEXT_EDGE_LIMIT=16384`, and `LG_CONTEXT_TARGET_TOKENS=500` were used. The runner requires telemetry `usage.input_tokens >= 500` for the new long case. For the extension run, successful `lg` request flow was 25 dataset requests (the original 24 plus one long record); there was also one synthetic identity request and one additional telemetry request, for 27 endpoint calls total by client flow, not independently server-instrumented. No server-side retry trace was available.

## Accepted HF configuration and context-edge follow-up

### Hugging Face repository facts (not a statement about the running server)

Read-only Hugging Face sources checked 2026-09-24:

- [Model card](https://huggingface.co/convaiinnovations/laya) describes root `convaiinnovations/laya` as ModernBERT-large, **421M** parameters, **512** context; its history shows branch `main` at short commit `55cf4c4`, updated 2026-09-24 05:39 UTC.
- [Hub model metadata](https://huggingface.co/api/models/convaiinnovations/laya) reports safetensors **421,293,830** parameters (421,293,827 F16 and 3 F32), and `lastModified=2026-09-24T05:39:22Z`.
- [Published Laya agent config at `55cf4c4`](https://huggingface.co/convaiinnovations/laya/resolve/55cf4c4/rl_agent_config.json): `max_len=512`, `head_max_len=192`, encoder `answerdotai/ModernBERT-large`.
- [Published encoder config at `55cf4c4`](https://huggingface.co/convaiinnovations/laya/resolve/55cf4c4/encoder/config.json): ModernBERT, 28 layers, hidden size 1024, 16 attention heads, vocab size 50,368, `max_position_embeddings=8192`.
- [Published tokenizer config at `55cf4c4`](https://huggingface.co/convaiinnovations/laya/resolve/55cf4c4/tokenizer/tokenizer_config.json): `model_max_length=8192`.
- [Published sequence builder at `55cf4c4`](https://huggingface.co/convaiinnovations/laya/resolve/55cf4c4/rl_common.py) truncates the state to remaining `max_len` room; [inference implementation](https://huggingface.co/convaiinnovations/laya/resolve/55cf4c4/rl_agent_api.py) returns `usage.input_tokens` as the summed attention mask length after sequence building.

These dimensions are not contradictory: the encoder/tokenizer advertise an 8,192 position capacity, while the *published Laya decision-agent config* sets an application-level 512-token `max_len`; the model card estimates that the English question/head budget (`head_max_len=192`) leaves roughly 320 tokens for state. The HF files are pinned to short revision `55cf4c4` for this report; user-approved assumption applies those published settings to localhost but does not claim a measured server revision.

Follow-up real inference ran 2026-09-24 17:37 UTC with the generated case. Run parameters: `lg 0.1.0`, `--model english`, endpoint `http://localhost:8000/v1/systemone`, query `Does this log contain an error?`, threshold/join threshold 0.5, `--max-fragment-bytes=16384`, `--max-line-bytes=16384`, assumed Laya `max_len=512/head_max_len=192`; full dataset SHA-256 `363a9f29fd92e6cf435224c97b8d17c2c3e7bfc0ed785d83d20b9c5b9957c148`. Input was 10,215 bytes as one physical line. `lg` selected the complete line with probability **0.8721** (process wall latency **1,400 ms**). A separate POST with the same model, state and single `match` question returned `model=laya-rl-agent`, `routing.model=english`, `routing.repo=convaiinnovations/laya`, and **`usage.input_tokens=512`**. In the extension run, flow-derived `lg` dataset calls total 25 (old 24 plus one long record), plus one metadata identity request and one context-usage request: **27 endpoint requests by client flow**, not independently server-instrumented. The captured endpoint response, matching `lg` JSON result, run parameters, timing, and input hash are retained in [`evidence/near512-run.json`](evidence/near512-run.json); the generated synthetic input is reproducible from its corpus row. Under the user-approved HF-config assumption and the published implementation's usage semantics, this is a real inference sequence at the published 512-token limit (100% occupancy), unlike the former 124-byte sample (which remains a client-byte-edge-only example). The server's loaded revision/config is not represented as independently verified.
