# Spec Delta

## MODIFIED Requirements

### Requirement: Сохранение и валидация происхождения

Система SHALL сохранять полученный `file` как непрозрачную идентичность источника, включая `STDIN`, и переводить нумерацию строк ast-grep с нуля к единице для общего вывода. Байтовые диапазоны остаются нулевыми полуоткрытыми [start,end). Все координаты SHALL быть неотрицательными целыми, диапазоны — упорядоченными; разность байтовых границ SHALL равняться UTF-8-размеру `text`. Число LF в `text` SHALL согласовываться с разностью начальной/конечной строк. Проверка недостающей информации о префиксе исходной строки не выдумывается. Неверная запись завершается ошибкой 2 с местоположением в JSONL. `jev-grep` SHALL NOT повторно открывать исходный файл, исправлять upstream-координаты или выдавать их за проверку актуальности файла.

#### Scenario: UTF-8 и CRLF
- **WHEN** корректное совпадение содержит кириллицу и CRLF
- **THEN** исходный текст сохраняется, байтовые границы не пересчитываются по нормализованной строке, а строковые координаты преобразуются без смещения

#### Scenario: Несогласованная длина
- **WHEN** разность `range.byteOffset.end/start` не равна размеру `text` в UTF-8
- **THEN** запись отклоняется до вызова модели

### Requirement: Потоковая обработка готовых кандидатов

Система SHALL выдавать выбранное корректное совпадение после его оценки без ожидания EOF JSONL. Порядок совпадений соответствует порядку входа. Пересекающиеся и повторяющиеся совпадения SHALL оставаться отдельными кандидатами: политика выбора AST-узлов принадлежит upstream. Кандидат больше `--max-fragment-bytes` SHALL завершаться ошибкой, поскольку его разбиение изменило бы выбранную upstream структурную единицу. `jev-grep` не запускает ast-grep и не выбирает грамматику.

#### Scenario: Пересекающиеся узлы
- **WHEN** upstream передал класс целиком и его метод и оба прошли отбор
- **THEN** выдаются два результата с собственными диапазонами без скрытой дедупликации

#### Scenario: Большая функция
- **WHEN** `text` одного кандидата превышает предел фрагмента
- **THEN** `jev-grep` сообщает ошибку и рекомендует уменьшить upstream-кандидат либо настроить предел, не выдавая часть функции как целую

## ADDED Requirements

### Requirement: Документированный конвейер для изменённых файлов

Документация SHALL предоставлять проверенный shell-конвейер Git → список изменённых существующих файлов → ast-grep JSONL → `jev-grep --input-format ast-grep`. Пример SHALL явно определять baseline и анализируемую версию файлов, сохранять пути с пробелами через NUL-разделение, не сканировать текущий каталог при пустом списке и передавать ошибки upstream через `pipefail`. В минимальном примере отбираются AST-узлы всех выбранных изменённых файлов, а не только узлы пересекающие hunks; это SHALL быть явно сказано. Удалённые файлы не передаются в ast-grep текущего дерева. Документация SHALL NOT предлагать разбирать сырой patch как исходную программу или обещать обнаружение удалённого поведения при анализе только новой версии. Данная возможность SHALL NOT добавлять встроенные Git/diff/AST readers в CLI.

#### Scenario: Изменённый файл с пробелом
- **WHEN** выбранный Git baseline содержит изменение существующего исходного файла с пробелом в пути
- **THEN** документированный конвейер передаёт его как один путь и сохраняет upstream-координаты кандидатов

#### Scenario: Нет подходящих файлов
- **WHEN** Git не возвращает подходящих существующих исходников, в том числе при одних удалениях
- **THEN** ast-grep не запускается без путей, полный репозиторий случайно не сканируется и платных оценок нет
