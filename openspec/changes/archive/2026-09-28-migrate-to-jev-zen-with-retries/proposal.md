# Proposal

## Why

Проекту нужен единый переход на Jev через OpenCode Zen: совместимый System One клиент уже существует, но defaults, публичные имена и документация относятся к прежнему runtime. Работа через облачный gateway также требует ограниченных повторов временно неуспешных запросов вместо немедленного прерывания поиска.

## What Changes

- **BREAKING**: пакет и единственный бинарник — `jev-grep`; настройки — `JEV_GREP_API_URL`, `JEV_GREP_MODEL`, `JEV_GREP_API_KEY`, без старых CLI/env-алиасов. Флаги переопределения сохраняются.
- Default endpoint — `https://opencode.ai/zen/v1/systemone`, модель в каждом запросе — `jev-1.13`. Бесплатная версия выбирается явно. Существующие вопросы `noul`, алгоритм группировки и форматы результатов сохраняются.
- Временные HTTP/сетевые ошибки повторяются ограниченно, с exponential backoff, jitter и `Retry-After`; `--timeout` ограничивает всю модельную оценку, включая попытки, чтение ответа и ожидание. Некорректные ответы и ошибки авторизации не повторяются.
- Проектный `fnox.toml` передаёт ключ Zen из OS keychain только дочернему процессу; ввод ключа выполняется пользователем локально.
- Обновляются README, deployment guide, действующие и архивные спецификации/документы. В исходном дереве остаётся ноль упоминаний прежней модели, включая архив; прежние фактические отчёты и raw evidence удаляются, а не переименовываются в результаты Jev. Git history не переписывается.
- Документация показывает внешний конвейер Git → выбор изменённых файлов → ast-grep → `jev-grep`, объясняет область выбора и отличие поиска по текущему коду от оценки самого diff. Встроенный diff-parser не добавляется.
- `docs/BACKLOG.md` фиксирует пять отложенных направлений: estimate, методика оценки качества, статистика, кэш ответов, параллелизм. Полный эксперимент качества и новый benchmark runner не входят в реализацию; необходим только небольшой live smoke-test интеграции и offline-проверки.

Этот change — самостоятельный актуальный план, заменяющий для реализации `migrate-to-jev-zen`, а не надстройка над ним. Старый change и его task-specific агенты при подготовке данного плана не изменяются; выполнять оба плана вместе нельзя. Реализация должна использовать задачи и назначения только этого change.

## Capabilities

### New Capabilities

- `jev-zen-integration`: имя и конфигурация CLI, System One через Zen, fnox, актуальные документы, очистка исторических материалов и минимальное подтверждение подключения.
- `bounded-api-retries`: классификация ошибок, ограничение попыток, общий deadline и отсутствие частичных результатов при повторе оценки.

### Modified Capabilities

- `log-fragment-selection`: новое имя команды и Jev; одна логическая оценка может включать несколько HTTP-попыток.
- `code-fragment-input`: новое имя команды и документированный внешний конвейер для изменённых файлов.
- `located-search-output`: ошибка временной HTTP-попытки становится окончательной только после исчерпания политики повторов; коды завершения и уже выданные результаты сохраняются.

## Impact

- `Cargo.toml`, `Cargo.lock`, `src/main.rs`, `src/api.rs`, существующие Rust/Python-тесты: переименование, конфигурация, retry и контрактные проверки. Базовый blocking reqwest/serde_json сохраняется; SDK и универсальный слой провайдеров не нужны.
- `fnox.toml`, `.gitignore`, `docs/deployment.md`: локальное хранение ключа и воспроизводимый запуск.
- `README.md`, новый `docs/BACKLOG.md`, архивный эксперимент и документы OpenSpec: актуализация, удаление недостоверных для Jev evidence, сохранение полезного синтетического корпуса как неисполненного материала для backlog.
- Основные specs синхронизируются при реализации. Текущий change добавляет только planning-артефакты; проектный код и документы вне него сейчас не меняются.
