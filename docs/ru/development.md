# Проверки для разработчиков

[English](../development.md) | **Русский** · [Документация](README.md)

## Настройка

Установите [mise](https://mise.jdx.dev/getting-started.html) **2026.11.1 или новее**
до запуска команд репозитория: старая версия не загрузит эту конфигурацию,
даже при наличии закреплённого mise в проекте. Изучите `mise.toml` и `hk.pkl`,
затем запустите из корня репозитория; менять глобальную конфигурацию mise не нужно:

```sh
mise trust
mise install
mise exec -- npm ci
mise run hooks:install
```

Нативные запускатели hooks hk находят mise через `PATH`. Во всех терминалах
разработчика и GUI-клиентах Git через `PATH` должен быть доступен mise
**2026.11.1 или новее**.

`mise.toml` фиксирует версии инструментов и определяет задачи; `hk.pkl` объединяет
проверки Git hooks и всего проекта. Используйте закреплённые инструменты вместо
глобальных версий. После изменений npm lockfile повторите `npm ci` через mise.
Основной Python 3.12.16 используется для acceptance-тестов и release tooling;
Python 3.14.10 установлен дополнительно для вспомогательного генератора агентов.

## Проверки

```sh
mise run check
```

Это полный набор проверок CI: он должен пройти перед завершением работы.
Pre-commit выполняет быстрые проверки staged-файлов без автоисправлений и
добавления изменений в индекс; commit-msg запускает Commitlint; pre-push выполняет
`mise run check:offline` для всего проекта. Эта задача не обращается к OSV и
удобна для локальных итераций, но не заменяет полный набор проверок.
Hooks нужно установить в каждом клоне. Для явного применения поддерживаемых
исправлений используйте `mise run fix`, затем просмотрите diff и повторите проверки.

Сохраняются форматирование Rust, Clippy, сборка и Rust-тесты, Python acceptance-тесты
и JavaScript-тесты release tooling. Добавляются Ruff для Python, Oxlint/oxfmt для
JavaScript, cargo-machete для неиспользуемых Rust-зависимостей, jactionlint для
workflows и закреплённый стабильный Betterleaks для поиска секретов. Точные версии
и проверяемые пути определяются конфигурационными файлами.

`mise run check:release` запускает `npm run test:release`
(`node --test scripts/*.test.mjs`). Эти тесты автоматизации релизов используют mock GitHub API
для проверки оркестрации, валидации точного head, публикации и повторных запусков.
Полные наборы Rust- и Python-тестов остаются частью `mise run check`.

Для проверки выбранной ветки на трёх платформах в GitHub используйте
[проверку сборок без публикации](releasing.md#проверка-сборок-без-публикации).
Она выполняет полный набор проверок и загружает архивы Linux/macOS/Windows
без создания или слияния release PR и без публикации релиза.

Acceptance-тесты используют Python standard library и локальный mock HTTP API.
Они проверяют группировку при заданных модельных ответах, форматы входа/вывода,
координаты, лимиты, фильтры и ошибки. Сервер Jev on OpenCode Zen и веса не требуются;
точность настоящей модели эти тесты не измеряют.

## Безопасность и найденные проблемы

```sh
mise run check:security
```

`mise run check` включает эту задачу безопасности: OSV-Scanner проверяет явно
заданные `Cargo.lock` и `package-lock.json`, а общий линтер workflows проверяет
правила и сроки действия исключений.
[Security workflow](../../.github/workflows/security.yml) также запускает её
отдельно по расписанию или вручную. Данные об уязвимостях могут измениться после
успешного полного прогона; запуски по расписанию выявляют вновь опубликованные
уязвимости и обеспечивают истечение сроков согласованных исключений workflows
и OSV даже без изменений кода.

Исправляйте причины находок, повторяйте соответствующую проверку, затем полный
набор. При блокировке сохраняйте полный вывод ошибки и сообщайте причину.
Подавления, baselines, отключение правил и пропуск проверок требуют явного решения
человека. Для согласованного исключения укажите причину, затронутый путь и правило.
Исключения безопасности также должны иметь срок действия, истечение
которого блокирует проверку; даты в комментарии недостаточно.

Согласованное [исключение jactionlint](../../.github/jactionlint.yaml) относится
только к `dangerous-triggers` в `.github/workflows/dependabot-auto-merge.yml`:
привилегированный `workflow_run` сливает точный проверенный head Dependabot или
сгенерированного release-please PR без выполнения кода PR. Для release PR также
обязательны проверки workflow/задач, бота, репозитория, ветки, меток и файлов,
описанные в [руководстве по релизам](releasing.md#защищённое-автоматическое-слияние-pr-ботов).
Срок действия — **2027-02-04**; просроченное исключение приводит к ошибке проверки
workflows.

Временное [исключение OSV](../../osv-scanner.toml) относится к
**GHSA-g3hv-75wg-m249** в `package-lock.json` по цепочке
`release-please@17.11.2 → @google-automations/git-file-utils@3.2.1 → minimatch@10.2.6`.
Исправление начинается с minimatch 11.0.1 вне диапазона `^10.2.4` родительского
пакета. Согласованное пользователем исключение истекает **2026-12-05 в 00:00 UTC**;
после этого OSV перестаёт игнорировать эту уязвимость. Удалите исключение, когда
станет доступно совместимое исправление зависимости upstream.

Миграция удаляет 18 из 19 уязвимостей старого графа зависимостей; эта одна остаётся
временно принятой. `npm audit` по-прежнему сообщает о ней, даже если настроенная
проверка OSV проходит. Успешные проверки не означают отсутствие уязвимостей.
В новом графе release tooling нет bundled dependencies; сам npm CLI не изменён.
Приватный корневой пакет инструментария не обязан объявлять версию: версию
выпускаемого Rust-пакета хранят Cargo и manifest release-please.

Обновляйте английские и русские руководства вместе. Для генерируемых страниц
`openwiki/` следуйте `AGENTS.md`: меняйте исходники/документацию, а не
сгенерированные страницы, если явно не запрошено обратное.

Автоматические релизы из `main`, Conventional Commits и проверки release tooling
описаны в [руководстве по выпуску релизов](releasing.md).
